# Урок 00. Окружение

> Время: 1–2 часа. Цель: поднять стенд, освоить psql как основной инструмент и понять, как устроена автопроверка.

## 1. Запуск

```bash
make install          # uv создаёт .venv и ставит зависимости по uv.lock
make up-oltp          # PostgreSQL 18 в Docker на порту 55432
make seed-test        # детерминированный мини-датасет в БД shop_test (для тестов)
make seed SCALE=small # датасет для экспериментов в БД shop: ~100k заказов, ~430k событий
make psql             # консоль
```

Масштабы: `tiny` (тесты) → `small` (секунды) → `medium` (~1 млн заказов, ~4 млн событий, около минуты)
→ `large` (~10 млн заказов, ~40 млн событий, ~10 минут и ~15 GB). `medium` понадобится с урока 04,
`large` — в OLAP-части.

Параметры подключения — в `.env` (host `localhost`, port `55432`, user/password `student`).
Порт нестандартный, чтобы не конфликтовать с локальным PostgreSQL.

`make down` останавливает контейнеры с сохранением данных; `make reset-oltp` удаляет кластер целиком.

## 2. psql — твой главный инструмент

GUI-клиенты удобны, но в продакшне у тебя будет ssh и psql. Выучи минимум:

| Команда | Что делает |
|---|---|
| `\dt+` | таблицы с размерами |
| `\d orders` | структура таблицы: колонки, индексы, ограничения, FK |
| `\di+` | индексы с размерами |
| `\x auto` | вертикальный вывод широких строк |
| `\timing on` | время выполнения каждого запроса |
| `\e` | открыть последний запрос в `$EDITOR` |
| `\i file.sql` | выполнить файл (например, своё решение) |
| `\watch 1` | повторять последний запрос каждую секунду (понадобится при наблюдении за блокировками) |
| `\set ON_ERROR_ROLLBACK interactive` | ошибка не убивает всю открытую транзакцию |
| `\conninfo`, `\l`, `\c shop_test` | где я, какие есть БД, переключиться |
| `\sf func`, `\df` | исходник функции / список функций |
| `\?`, `\h SELECT` | справка по psql / по синтаксису SQL |

Положи в `~/.psqlrc` (применится ко всем сессиям):

```
\set QUIET 1
\pset null '∅'
\x auto
\timing on
\set ON_ERROR_ROLLBACK interactive
\set PROMPT1 '%n@%/%R%# '
\set QUIET 0
```

`\pset null '∅'` особенно важен: иначе NULL и пустая строка в выводе неотличимы, а в уроке 01 это
критично.

## 3. Как устроена автопроверка

- Каждый урок: `README.md` (теория), `tasks.md` (задачи), `sql/task_NN.sql` (твои решения), `tests/`.
- `make test L=01` запускает pytest. Он берёт твой SQL, выполняет его в **read-only** транзакции на
  `shop_test` с таймаутом 10 с и сравнивает результат с эталоном.
- Эталон хранится как хеши строк — ответ подсмотреть нельзя, но тест подскажет, *что* не так:
  имена колонок, число строк или первая расходящаяся строка.
- Числа сравниваются после округления до 2 знаков, так что `10`, `10.0` и `10.00` — одно и то же.
- Если датасет в `shop_test` испорчен или устарел, тесты перегенерируют его сами.

## 4. Разминка на Python

Во всём курсе Python — это драйвер `psycopg` 3 без ORM. Создай `lessons/00-setup/py/hello.py`:

```python
from common.db import connect

with connect() as conn:
    country = "AM"
    rows = conn.execute(
        "SELECT id, full_name, city FROM users WHERE country = %s ORDER BY id LIMIT 5",
        (country,),
    ).fetchall()
    for r in rows:
        print(r)
```

Запуск из корня репо: `PYTHONPATH=. uv run python lessons/00-setup/py/hello.py`.

**Задание 0.1.** Перепиши запрос так, чтобы страна подставлялась через f-string, и передай
`country = "AM' OR '1'='1"`. Что вышло? Затем объясни (в `notes/00.md`), почему вариант с `%s`
безопасен: параметры отправляются на сервер **отдельно** от текста запроса (протокол extended query:
Parse → Bind → Execute), и сервер никогда не интерпретирует их как SQL. Это не «экранирование
кавычек», это другой механизм.

**Задание 0.2.** Выполни в psql `\d+ events` и `\dt+`. Посчитай, сколько байт на диске приходится на одну
строку `events` (`pg_relation_size('events') / count(*)`), и сравни с суммой размеров её колонок
(bigint — 8 байт, timestamptz — 8, короткий text — 1 + длина). Откуда разница? Запиши гипотезу —
ответ будет в уроке 03 про устройство страниц и кортежей.

**Задание 0.3.** Открой [datasets/generator.py](../../datasets/generator.py) и найди, где и почему
внешние ключи создаются после загрузки данных. Прикинь, что стоило бы проверять FK на каждой из
400 тысяч вставленных строк.
